# Защита фотографий

`GET /media/{id}/{size}` требует действующую сессию и проверяет доступ к фотографии при каждом запросе. Знание UUID не даёт права доступа. Фотография доступна владельцу либо через доступный ему ресурс: профиль, пост, комментарий, чат, история, статья, точка маршрута или эмодзи сообщества. Неопубликованное фото доступно только владельцу. Для просмотра фотографий требуется вход, в том числе для аватаров.

Браузер получает HttpOnly-cookie `media_access` при входе и обновлении сессии. Она ограничена путём `/media/`, имеет SameSite=Strict, использует `COOKIE_SECURE` и принимается только маршрутом чтения фотографий. API по-прежнему требует Bearer-токен. Завершённая сессия и заблокированный аккаунт не проходят проверку даже с сохранённой cookie.

Ответы фотографий используют `Cache-Control: private, no-store`. Новые ссылки содержат `acl=2`, чтобы браузер не использовал старый публичный кеш. Уже скачанные пользователями копии отозвать невозможно.

## При обновлении сервера

1. Пересоберите API на Go 1.27.4 или более новой исправленной версии. Dockerfile закрепляет Go 1.27.4; старый контейнер сам не обновится.
2. Если используется S3, запретите анонимное чтение объектов `photos/*` в политике бакета и CDN. Доступ к этим объектам должен иметь только сервер. Приложение больше не перенаправляет фотографии на `MEDIA_CDN_URL`, а выдаёт их через проверку доступа.
3. Удалите старый кеш `photos/*` на CDN и прокси. Проверьте, что прямой адрес объекта недоступен анонимному клиенту. Удаление редиректа в приложении не меняет внешнюю политику бакета.
4. Обновите страницу приложения или войдите заново для получения cookie. В production включите HTTPS и `COOKIE_SECURE=true`.
5. Проверьте фото владельца, закрытый профиль, личное сообщение и запрос без входа. Без сессии ожидается 401, для чужого недоступного фото — 404.
