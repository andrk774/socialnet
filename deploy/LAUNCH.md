# Перед открытием для людей

Список дел, которые нельзя сделать кодом. Отмечайте `[x]` и дату. Это
памятка, а не юридическая консультация: финальное слово — за юристом.

## 1. Юрист

Показать юристу (лучше с опытом в IT и персональных данных):

- [ ] `/legal/terms` — пользовательское соглашение: ответственность за походы
      (организатор — частное лицо, сайт не турагент), модерация, блокировки.
- [ ] `/legal/privacy` — политика обработки персональных данных: какие данные,
      зачем, сроки хранения, где сервер (в России), кому передаются (почта,
      ЮKassa, Яндекс SmartCaptcha).
- [ ] `/legal/consent` — согласие на обработку ПДн (отдельный документ,
      152-ФЗ ст. 9) и согласие на распространение (ст. 10.1): профиль,
      записи и треки, видимые всем.
- [ ] Геоданные: треки и точки сбора — это ПДн. Прятать начало и конец трека
      (`hidden_ends_m`) уже умеем; юрист решает, нужно ли отдельное согласие.
- [ ] Возраст: сейчас в соглашении и согласии — только с 18 лет. Если
      хотите пускать с 14 — юрист переписывает согласие (нужно согласие родителей).
- [ ] Если включаете «Плюс» и сборы — оферта на платные услуги, порядок
      возврата, что такое «монеты» (не электронные деньги, не выводятся).
- [ ] Рекомендательная лента («Мои ленты», антенны) — по 149-ФЗ ст. 10.2-2
      правила рекомендаций должны быть опубликованы, если алгоритм
      подбирает записи по данным пользователя. Спросить, подпадаем ли.

## 2. Роскомнадзор

- [ ] Уведомление об обработке ПДн — на https://pd.rkn.gov.ru (раздел
      «Уведомления»). Нужны: оператор (ИП/ООО/физлицо), цели, категории
      данных, правовое основание, меры защиты, ответственный за обработку,
      место базы данных (адрес дата-центра, страна — Россия).
- [ ] Ответственный за обработку ПДн назначен (приказ, если ООО).
- [ ] Сервер и копии в России (242-ФЗ): Timeweb Cloud — да; бакет копий
      тоже в российском регионе (`BACKUP_S3_REGION=ru-1`).
- [ ] Реестр организаторов распространения информации (ОРИ): обязателен
      после уведомления РКН; личные сообщения в сервисе есть — быть готовым.
- [ ] Порядок ответа на запросы субъектов ПДн: 10 рабочих дней. Удаление —
      сам пользователь, «Безопасность → Удалить аккаунт». Кнопки выгрузки
      своих данных пока нет — запросы на выгрузку обрабатывать вручную.

## 3. Платежи (если включаете ЮKassa)

- [ ] Статус: самозанятый, ИП или ООО (для самозанятых у ЮKassa свои
      ограничения — уточнить, подходит ли «Плюс» и пополнение кошелька).
- [ ] Договор с ЮKassa, магазин прошёл проверку, на сайте: оферта,
      контакты, реквизиты, описание услуг и цены (требование ЮKassa).
- [ ] 54-ФЗ: чеки. Подключить «Чеки от ЮKassa» или свою онлайн-кассу;
      `YOOKASSA_VAT_CODE` согласовать с бухгалтером.
- [ ] В `.env`: `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`; в личном кабинете
      ЮKassa — адрес уведомлений `https://ДОМЕН/api/v1/payments/yookassa`.
- [ ] Тестовый платёж и возврат на боевом магазине.

## 4. Техника

- [ ] Почта: свой домен, SPF, DKIM, DMARC; письмо подтверждения доходит
      до Яндекса, Mail.ru и Gmail, не в спам.
- [ ] Яндекс SmartCaptcha: ключи `CAPTCHA_SITE_KEY` и `CAPTCHA_SECRET`,
      в настройках капчи — ваш домен. Проверить регистрацию вживую: виджет
      появляется, без галочки «Создать» отвечает ошибкой.
- [ ] `BACKUP_ENC_KEY` сохранён в менеджере паролей **вне** сервера.
- [ ] Копии уходят во внешний бакет (`BACKUP_S3=true`), в админке
      «Резервная копия» — зелёная.
- [ ] Учения восстановления пройдены (раздел 5).
- [ ] Мониторинг включён, оповещения приходят (Grafana → Alerting).
- [ ] Тайлы карты: свой сервер или платный источник, когда трафик вырастет
      (правила tile.openstreetmap.org — только небольшой трафик).
- [ ] Модераторы назначены, знают, где «Админка → Жалобы».

## 5. Учения: восстановление из копии

Раз в квартал и после крупных изменений базы. На **отдельном** сервере
(самый дешёвый в Timeweb на час), не на боевом.

1. Сервер с Docker: `deploy/setup-server.sh` или вручную `apt install docker.io docker-compose-v2 git`.
2. `git clone` репозитория, в `.env` — **прежние** `BACKUP_ENC_KEY` и
   `JWT_SECRET`, остальные пароли новые (`openssl rand -hex 32`).
3. Скачать последний дамп из бакета (`backups/socialnet-….dump.enc`).
4. `deploy/restore-drill.sh /root/socialnet-….dump.enc`
5. Скрипт напечатает отчёт: время восстановления (RTO), возраст данных в
   копии (RPO), число пользователей, записей, походов. Перенести в журнал ниже.
6. По желанию: `docker compose run --rm api restore-media` — проверить, что
   фото тоже возвращаются (займёт дольше).
7. Удалить учебный сервер.

То же самое, кроме медиа, CI проделывает на каждом коммите (задание
`compose`, шаг «Восстановление из резервной копии с нуля»).
